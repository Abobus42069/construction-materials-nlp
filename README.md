# Materials NLP

Самостоятельный NLP-компонент дипломной ИАС анализа строительных материалов. Принимает JSONL парсера версии 2.0 и создаёт аннотации версии 1.0 с проверяемыми источниками. Не импортирует код парсера, не изменяет его данные и не требует общей БД.

Версия 0.1.0 — лингвистическая база сравнения на правилах и словарях, без обученной модели, внешних API и дополнительных runtime-зависимостей. Это основа для сравнения с последующими моделями.

## Запуск

Python 3.10+, из папки этого репозитория:

```powershell
python -B -m materials_nlp extract ../tn_materials_parser/validation_live/nlp.jsonl --out output/annotations.jsonl
python -B -m materials_nlp evaluate data/smoke_gold.jsonl --out output/evaluation.json
python -B -m unittest discover -s tests -v
```

Установка пакета: `python -m pip install -e .`, после неё доступна команда `materials-nlp`. Путь к входному JSONL произвольный; соседняя папка используется только как пример. Git-репозиторий независимый; удалённый репозиторий автоматически не создаётся.

## Возможности

- Температуры нанесения, эксплуатации, хранения, транспортирования, твердения, основания и баллона: диапазоны в °C и явные границы.
- Явно сформулированное назначение, запреты и формулировки «не рекомендуется» как разные состояния.
- Формулировки совместимости с исключениями, без вывода о разрешении применения.
- Простые числовые характеристики, некоторые единицы и операторы сравнения.
- Нормативные формулировки как кандидаты, привязанные к документу и явно указанному пункту.

Неизвестный температурный контекст не подменяется нанесением. Хранение и перевозка в одном предложении отмечаются как неоднозначные. Неизвестные единицы и сложные значения остаются без нормализации.

## Выход

- `annotations.jsonl`: кандидаты аннотаций со статусом `candidate`, без выдуманной уверенности.
- `annotations.contexts.jsonl`: метаданные и связи из исходного экспорта.
- `annotations.report.json`: статистика, необходимость OCR и ограничения запуска.

Каждая аннотация содержит субъект, исходную формулировку, значение, единицу, оператор, условия, исключения, версию правил и evidence. Цитата проверяется как точный срез записи. Позиции в чанках пересчитываются в позиции страницы/раздела; для строк свойств и фрагментов применимости позиции на странице остаются null. ID детерминированы.

Нормативные утверждения не переносятся автоматически на материалы. Актуальность, обязательность и соответствие требованиям не устанавливаются. Оригиналы документов и источники остаются в корпусе парсера, ссылка на них сохраняется в evidence.

## Оценка

`data/smoke_gold.jsonl` — небольшой синтетический набор с заданными ожидаемыми результатами. Метрики считают точное совпадение набора predicate/value/unit/operator/polarity внутри примера. Границы цитат проверяются тестами. Эти примеры использованы при разработке правил и не являются независимой оценкой качества на реальных документах.

Для дипломного эксперимента нужно разметить реальные документы и разделить материалы/семейства документов на разработку и независимую проверку. Соседние чанки одного документа не должны попадать в разные выборки.

## Ограничения и дальнейшая работа

Нет обученной модели, OCR, восстановления таблиц и связей между чанками. Многострочные и оборванные требования требуют просмотра полного документа. Формулировки из HTML/PDF сохраняются как отдельные свидетельства без автоматического разрешения конфликтов. Аннотации не являются заключением о пригодности.

Далее: реальные ручные аннотации, многострочный контекст, словари оснований и конструкций, независимая оценка ошибок запретов, подключение модели с тем же выходным контрактом.
